1. LATAR BELAKANG
-----------------
Berdasarkan materi Week 7 "Transisi dari PHP OOP menuju pola MVC",
dilakukan implementasi pemisahan tanggung jawab menjadi Model, View, Controller
untuk meningkatkan struktur dan maintainability kode.

Prinsip MVC yang diterapkan:
- Model     : Mengelola data dan logika bisnis
- View      : Bertanggung jawab pada tampilan/presentasi
- Controller: Menangani request, memanggil Model, mengirim data ke View

Alur Request Flow:
User → Request → Controller → Model → Controller (prepare data) → View → HTML Response

6. REVIEW KUALITAS MVC
----------------------
1. Bagian mana yang lebih mudah dikelola setelah dipisahkan menggunakan MVC?
   - Setelah pemisahan MVC, logika data (Model) terpisah dari tampilan (View) dan alur
   (Controller). Sehingga lebih mudah menambah fitur, mengubah tampilan tanpa
   menyentuh logika, dan maintenance lebih terstruktur.

2. Apa yang terjadi ketika request masuk ke Controller?
   - Request di-routing oleh core/App.php berdasarkan URL (?url=...), App akan
   menginstansiasi Controller yang sesuai, memanggil method yang diminta,
   dan meneruskan parameter jika ada.

3. Bagaimana Controller memperoleh data dari Model?
   - Controller memanggil $this->model('ServiceModel') yang mewarisi dari base
   Controller. Model kemudian membaca data dari services.json melalui helpers
   dan mengembalikan data ke Controller.

4. Bagaimana data sampai ke View?
   - Controller menyiapkan array $data berisi informasi yang dibutuhkan, kemudian
   memanggil $this->view('view/path', $data). View mengakses $data untuk
   menampilkan informasi secara dinamis.

5. Bagian mana yang bertanggung jawab pada data, alur, dan tampilan?
   - Model (ServiceModel): bertanggung jawab pada data & akses data
   - Controller (ServiceController/HomeController): bertanggung jawab pada alur aplikasi
   - View (app/Views/*): bertanggung jawab pada tampilan/presentasi
